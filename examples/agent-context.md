# 如何设计 Agent 的上下文？

## 哪些信息，值得放进上下文？

一位用户问：“这双鞋还能退吗？”如果把他半年的聊天记录都交给 Agent，它可能先读到上次退货的经过，却漏掉这次订单里最关键的一句：昨天，客服答应为他延长退货期限。

> 我会先问：少了哪条信息，这道题的答案就可能反过来？

### 先还原这次决定

1. **认准订单。** 用户上个月也买过同款鞋。先用 `order_id` 对齐订单，再查签收时间，否则查得越细，答得越偏。
2. **找出例外。** 常规退货期已过，不等于这单不能退。保留客服承诺的原话、日期和适用订单，不要只留一句“沟通过售后”。

| 信息 | 放进来，还是先放一边？ |
| --- | --- |
| 订单与规则 | 保留签收日，以及下单时适用的条款。 |
| 历史对话 | 取回延期承诺；同款鞋的尺码咨询先不放。 |

---

### 用一对样例检查取舍

- **有承诺时：** 给出能核实的延期日期。如果只有用户转述，就追问承诺来自哪次对话，不直接答应退款。
- **没有承诺时：** 保持商品、签收日和提问不变，只拿掉那条承诺。看回答是否回到常规规则，而不是沿用上次结论。

我不会用~~读了多少条记录~~来判断设计好坏。更有用的信号是：当证据改变，回答会不会跟着变？如果两次都说“可以退”，我会回看第二次的上下文：是上次的承诺还留在里面，还是模型在没有依据时也给出了肯定答复？
