# 纸间 · 图文排版台

为文字创作者设计的本地工作台：Markdown → 杂志式分页 → 试配图 → 导出小红书图片。

## 打开

在本项目目录运行（Node.js 22+，推荐已安装 Google Chrome）：

```sh
npm install
npm start
```

用浏览器打开 <http://127.0.0.1:5267/>。仅监听本机。端口冲突时，可用 `PORT=5268 npm start`（地址的端口也要一起改）。没有 Google Chrome 时可用 `npx playwright install chromium`，也可在启动时用 `FOLIO_CHROME_PATH` 指定 Chrome 可执行文件。

## 同一 Wi‑Fi 上用手机打开

保持 `npm start` 运行，在同一目录另开终端执行：

```sh
FOLIO_LAN_HOST="$(ipconfig getifaddr en0)" node lan.cjs
```

在手机的 Safari 或 Chrome 中打开启动时显示的 `http://Mac的Wi‑Fi地址:5268/`。默认用户名为 `folio`，随机口令保存在本项目的 `.folio-data/lan-password.txt`。如果你确认信任网段里的所有设备，可以在启动命令前加 `FOLIO_LAN_OPEN=1`；这个模式下它们均可免登录查看和编辑稿件。两个入口读写同一份项目；不要在两个设备同时修改同一篇稿件。此入口使用 HTTP，仅在可信 Wi‑Fi 下使用，不要配置路由器端口转发。停止这个入口可在其终端按 Ctrl+C，不影响本机入口。Mac 睡眠、Wi‑Fi 地址改变或访客网络隔离可能导致手机打不开。若 Wi‑Fi 不是 `en0`，请在命令中填写实际私有 IPv4 地址。

## 第一次试用

1. 保留默认样稿，在右侧正文点「一位用户问……」那段，进入「试配图」。也可以左侧导入自己的 `.md`，点击「生成预览」。
2. 选中素材库的帆布鞋，切换段旁小图、段中横图或独立主图页。用「原版 / 试排」比较首尾分页和整篇页数。
3. 只有点「采用到文章」才会改变成稿；「暂不用」只关闭试排。候选图和上传图会保存在素材库，不用重画。
4. 需要直接写进 Markdown 的图片，可用「插入图片」或将本地图片拖入编辑区。工具把它存到本机，并插入标准 Markdown 图片引用。为了让预览与导出一致，不会抓取任意外链；请上传外部图片后插入。
5. 「本篇」选择排版预设，需要时再填本期题目、追问和封面图。标题留空从 Markdown 一级标题提取。默认是暖白砖红风、32 px 正文。整篇可以切到总览，也可以下载一页 PNG 或下载全篇 ZIP（批量上限 60 页）。

项目会保存在本目录的 `.folio-data/`，包括一份原稿、栏目设置、段落配图和素材。这个版本是**单项目本地工具**。导入新稿会替换当前稿文字并清空配图关联，素材会保留。需要长期归档多篇项目，可以停服务后备份整个数据目录，或用 `FOLIO_DATA_DIR=/自选目录 npm start` 切换项目。配图跟随内容未变的原段落移动；大幅编辑原段落后工具会提醒重新关联，不会自动错挂到其他段落。

支持常见标题、段落、强调、引用、列表、表格、代码和图片。若需指定分页，单独一行写 `<!-- pagebreak -->`。纯文字和已上传图片的排版/导出不需要 AI。

预览下方的「封面」「尾页」可快速定位对应页面；该页未启用时，按钮不可用。

## 在网页管理预设

打开设置弹窗的「预设管理」标签，可新建、编辑自定义预设，或将现有预设另存为新预设。预设可复用字体、字号、配色、栏目名、右上页眉、生图风格、封面和尾页开关、固定封面图、默认追问及互动文案。只有内置 Text（CLI 名称 `text`）只读，可以另存。自定义预设可删除，需确认；删除只从可选列表移除，备份保存在预设目录的 `.deleted/` 中，不影响已保存的稿件快照。

在左侧 Markdown 原稿上方选择「本篇预设」，再点「生成预览」，一次应用本篇信息和正文。更新预设不会重排已保存的稿件；如需应用新版，可点「重新套用」。标题、追问、封面图和段落插图是本篇自己的内容，不会被覆盖。封面图和追问在「封面与结尾」里，没有本篇封面图时才使用预设固定图；两处都不设图就是文字封面。本篇追问留空时使用预设默认追问。「仅本篇调整」可以临时覆盖排版规则，不会反写预设。

网页与命令行共用 `presets/`（或 `FOLIO_PRESETS_DIR`）。网页新建后，CLI 可立刻用同名 `--preset`。如果预设固定封面使用网页上传的图片，CLI 和网页也要使用同一个 `FOLIO_DATA_DIR`，默认是项目内的 `.folio-data/`。

## 命令行导出（CLI）

在项目目录运行：

```sh
# 将独立 Markdown 排成 3:4 图片，不覆盖网页稿件
npm run folio -- render ./article.md --preset ai-pm-indigo --out ./cards

# 读取网页里最近一次已保存的稿件（包括已采用的配图）
npm run folio -- export --current --out ./current-cards

npm run folio -- --help
```

输出目录包含按顺序编号的 1080 × 1440 PNG 和整篇 ZIP。已有同名文件时会报错，不会覆盖。可选 `--json` 返回机器可读的页数、路径和警告，方便脚本或助手调用。两个命令都不需要先启动网页，不会修改原稿、覆盖网页当前项目或触发生图。若网页使用自定义 `FOLIO_DATA_DIR`，`export --current` 也要使用同一个变量值。

**不指定预设时，CLI 使用 `ai-pm`（若存在）；否则用 Text，只出正文。** 想用带封面和尾页的版式时，可显式指定 `--preset ai-pm-indigo` 或另建一个预设。封面标题取稿件第一个一级标题（没有就用文件名）；不沿用示例文章的右上页眉、插画或案例。尾页默认用通用提问，可通过 `--question '你会先核实哪项信息？'` 换成本期问题，右上页眉由预设决定，内置预设默认留空，可用 `--header-right '第 02 题'` 临时覆盖。互动尾页的投票提示默认关闭，可用 `--vote` 开启，开启后放在互动区最后一行（不创建平台投票）。仅需正文时选 `--preset text`；也可以单独加 `--no-cover` 或 `--no-ending`。

**预设用来复用整套样式。** `npm run folio -- presets` 可以列出内置和自定义预设。把一个 JSON 放进本项目 `presets/`（也可用 `FOLIO_PRESETS_DIR` 换目录），以后用 `--preset 文件名`（不带 `.json`），或直接 `--preset ./layout.json`。参考 [靛蓝栏目预设](<presets/ai-pm-indigo.json>)：可以配置字体、字号、色系、封尾开关、尾页问题、投票开关、评论提示和三条互动文案。预设中的相对封面图片路径以预设文件目录为根。`--settings ./layout.json` 可再覆盖当次设置，其相对封面图片路径仍以 Markdown 目录为根；`--title`、`--body-size` 等命令行参数最后生效。`export --current` 仍沿用网页已保存的设置，也可临时覆盖，但不另套预设。

Markdown 可只含文本，也可引用稿件所在目录及其子目录中的 PNG / JPEG / WebP，如 `![案例图](./images/example.png)`；不抓取外链。文件名有空格时，用 `%20` 编码。

如果想直接使用 `folio` 命令，可以在本项目目录运行 `npm link`（要求你的 Node 全局 bin 目录已加入 PATH）；不安装全局命令也可用上面的 `npm run folio -- …`。

## 可选：启用 AI 配图

服务端支持 OpenAI Images API。把 `OPENAI_API_KEY` 设在启动进程的环境中，重启服务。不要把密钥写进 Markdown、网页或源码。默认模型是 `gpt-image-1`，可用 `OPENAI_IMAGE_MODEL` 修改；也可配置可信的兼容地址 `OPENAI_BASE_URL`（例如服务的 `/v1` 根路径）或 `OPENAI_IMAGE_ENDPOINT`（完整生成路径）。响应需要 `data[0].b64_json`。

只有用户在「试配图」里点「生成候选图」并确认后，才会发送所选段落和画面要求，可能产生服务费用。普通预览、试摆和导出不调用模型。未配置密钥时，仍可上传图片、使用示例素材、预览和导出。当前安装没有配置真实密钥；生图接口用本地假服务测试，不产生费用。
